# 世界杯方案推荐规则

基于 `server/core/plan-generator.js` → `generateExpertPlans()` 框架的世界杯赛事差异化规则。与常规方案相比，**核心差异在于新增「方向排名约束」和「推荐人数下限」**。

> **适用范围**：本规则仅适用于 **2026 年世界杯**联赛标签的比赛（即 `league` 或 `competition` 字段包含"世界杯"标签的场次）。非世界杯标签的比赛沿用常规方案生成规则。

---

## 通用数据源与术语

| 术语 | 含义 |
|------|------|
| **方向排行** | `ranking-list` API 返回的 `ranking` 数组，按 `expertCount` 降序排列 |
| **方向前 N 名** | 该方向在当前比赛日所有推荐方向中，按推荐人数排名 ≤ N |
| **推荐人数 ≥ K** | 该场次上该方向被专家推荐的 `recs.num` 总和 ≥ K |
| **合赔** | 两场赔率乘积（2 串 1 过关投注的回报倍数） |
| 投注金额 | 1000 元/方案（250注 × 10票 × 25倍 = 1000元） |

## 方案一：平、让平 × 让负（2 串 1）

```
┌──────────────────────────────────────────────────────────────┐
│  第一场：平 + 让平（双选）                                    │
│  第二场：让负                                                │
│  投注方式：2串1 混合过关                                      │
└──────────────────────────────────────────────────────────────┘
```

| 环节 | 条件 | 说明 |
|------|------|------|
| **比赛总数** | ≥ 3 场 | 当天可投注场次 ≥ 3 场 |
| **第一场选场** | 平/让平方向排前 3 名 + 推荐人数 ≥ 10 | 选当天推荐"平"或"让平"人数最多的比赛 |
| **第一场门禁** | SPF 平赔率必须有效（> 0） | 平赔率为 "-" 则整案跳过 |
| **第二场选场** | 让负方向排前 3 名 + 推荐人数 ≥ 10 | 选推荐"让负"人数最多的比赛（排除第一场已选）|
| **排除规则** | 第二场 ≠ 第一场 | 同场不混 |

**生成逻辑**：
```
1. 筛选 mList → 统计每个比赛的 recs 中 平、让平 的 num 总和
2. 取总和最大且 ≥10 的比赛 → 第一场（同时验证平赔率有效性）
3. 筛选剩余比赛 → 统计 让负 的 num 总和
4. 取总和最大且 ≥10 的比赛 → 第二场
5. 验证第一场 + 第二场方向均在当日排行前 3 名
```

## 方案二：总进球-2、3球 × 让负（2 串 1）

```
┌──────────────────────────────────────────────────────────────┐
│  第一场：总进球-2、3球（双选）                                │
│  第二场：让负                                                │
│  投注方式：2串1 混合过关                                      │
└──────────────────────────────────────────────────────────────┘
```

| 环节 | 条件 | 说明 |
|------|------|------|
| **比赛总数** | ≥ 3 场 | 当天可投注场次 ≥ 3 场 |
| **第一场选场** | 总进球-2、3球方向排前 3 名 + 推荐人数 ≥ 10 | 选推荐此方向人数最多的比赛 |
| **第一场赔率** | totalGoals[2] 和 totalGoals[3] 均有效 | 缺一则无法生成 |
| **第二场选场** | 让负方向 ≥ 10 人 | 推荐"让负"人数最多的比赛（排除第一场）|
| **合赔门槛** | ≥ 2.0 | 两场赔率乘积 ≥ 2.0，否则不生成 |

**差异对比（vs 常规方案二）**：
- 新增：当天比赛 ≥ 3 场
- 新增：两场方向均需排前 3 名
- 新增：每个方向推荐人数 ≥ 10
- 保留：让负 ≥ 10 人
- 保留：合赔 ≥ 2.0

## 方案五：平、让平 × 总进球-2、3球（2 串 1，交叉配对）

```
┌──────────────────────────────────────────────────────────────┐
│  第一场：平 + 让平（双选）                                    │
│  第二场：总进球-2、3球（双选）                                │
│  投注方式：2串1 混合过关（交叉配对取最优合赔）                 │
└──────────────────────────────────────────────────────────────┘
```

| 环节 | 条件 | 说明 |
|------|------|------|
| **比赛总数** | ≥ 4 场 | 当天可投注场次 ≥ 4 场 |
| **第一场选场** | 平/让平方向排前 3 名 | 所有比赛中推荐此方向人数排前 3 |
| **第二场选场** | 总进球-2、3球方向排前 3 名 | 所有比赛中推荐此方向人数排前 3 |
| **交叉配对** | A池 × B池 排除同场 | 遍历所有组合取合赔最高 |
| **合赔门槛** | ≥ 1.5 | 最优组合的合赔必须 ≥ 1.5 |

**候选池构建**：
```
A 池（平、让平）：
  ├─ 方向排前 3 名
  ├─ 推荐人数 ≥ 3
  └─ 赔率 ≥ 1.0

B 池（总进球-2、3球）：
  ├─ 方向排前 3 名
  ├─ 推荐人数 > 0
  ├─ 赔率 ≥ 1.0
  └─ totalGoals[2] 和 totalGoals[3] 均有效
```

**差异对比（vs 常规方案五）**：
- 新增：两场方向均需排前 3 名
- 调整：≥ 4 场（常规方案 ≥ 6 场）
- 保留：交叉配对取最优合赔
- 保留：合赔 ≥ 1.5

## 实现建议

> **已实现**：代码位置 `server/core/plan-generator.js` → `generateExpertPlans()`，通过 `isWorldCup` 检测联赛标签自动切换世界杯 / 常规分支。

### 实现架构

```
generateExpertPlans(mList, matchDataMap, dateStr)
├── isWorldCup 检测：mList 中任一 match.leagueName 包含"世界杯"
├── getWCRanking()：基于 matchDataMap.recs 自建方向排行（免外部 API）
├── isDirectionTopN(matchId, directions, topN)：排行前 N 检查
├── getWCDirectionCount(matchId, directions)：复合方向推荐人数
│
├── [世界杯分支] isWorldCup === true
│   ├── 方案一：≥3场 + 双场均前3 + 各≥10 + 平赔率门禁
│   ├── 方案二：≥3场 + 双场均前3 + 各≥10 + 合赔≥2.0 + totalGoals[2][3]有效
│   ├── 方案三：第二场前3 + 胜≥25 + 合赔≥2.0
│   ├── 方案四：≥3场 + 双场均前3 + 胜≥25
│   ├── 方案五：≥4场 + 双场均前3 + 交叉配对 + 合赔≥1.5
│   ├── 方案六：≥2场 + 该场前3
│   ├── 方案七：有单关场次 + 推荐人数≥5
│   └── 方案八：有单关场次 + 胜≥100（世界杯专属）
│
└── [常规分支] isWorldCup === false
    └── 保持原有逻辑不变
```

### 排行算法

`isDirectionTopN(matchId, directions, topN)` 的计算逻辑：

1. 收集当日所有比赛的 `(matchId, direction, count)` 三元组
2. 按 `count` 降序排列
3. 找出指定比赛在目标方向上的最高 `count` 值
4. 统计比该 `count` 值严格大的不同计数值个数
5. 若该个数 < `topN`，则判定为"排前 topN 名"

这样处理了多人同分的情况：若第 3 名有并列，则并列者均视为前 3 名。

### 调用方

`generateExpertPlans` 被 3 处调用（均在 `server/index.js`），无需修改调用方：

| 调用方 | 用途 |
|--------|------|
| `plan-list` API | 今日方案页展示 |
| `income-stats` API | 方案收入统计（历史回测） |
| `profit-7d` API | 7 天利润走势 |
