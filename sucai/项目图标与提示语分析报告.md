# JC-ZJFA 项目图标与提示语分析报告

> 分析日期：2026-06-04

## 一、图标使用情况分析

### 1.1 图标分布概览

| 类别 | 位置 | 数量 | 实现方式 |
|------|------|------|---------|
| **导航返回箭头** | `index.html` L29 | 1个 | Inline SVG (48x48) |
| **首页快捷菜单** | `index.html` L49-107 | 7个 | Inline SVG (64x64) |
| **底部 TabBar** | `index.html` L114-130 | 5个 | Inline SVG (24x24) |
| **日期左右箭头** | `main-fusion.js` `_ensurePage()` | **重复8次** | 相同 SVG path (24x24) |
| **下拉菜单箭头** | `main-fusion.js` 各 DD 控件 | **重复10+次** | Inline SVG polyline |
| **AI 弹窗 emoji** | `app.js` | 多种 | `💡🏆⚽📊` 内联字符 |
| **数据健康 emoji** | `data-health.js` | 多种 | `📊📈⚠️✅` 内联字符 |
| **外部图片资源** | `preview/assets/` | 4个文件 | SVG/PNG |
| **导航 Logo** | `index.html` L27 | 1个 | `<img>` 外部 PNG |
| **功守道弹窗图标** | CSS `.gs-title-icon` | 动态 | `<img>` 外部文件 |
| **小程序 TabBar** | `custom-tab-bar/` | 4个 | CSS 伪元素纯绘制 |

### 1.2 合理性评估

#### ✅ 做得好的地方

1. **TabBar 全部使用 Inline SVG**：无需额外 HTTP 请求，渲染即时，支持 `currentColor` 继承主题色，与底部激活光晕（紫色 `#A78BFA`）完美配合。

2. **菜单图标使用 Inline SVG**：7 个菜单项各有独立 SVG，设计语义清晰（方案=文档+勾选、收入=¥字同心圆、量化=3x3矩阵、排名=柱状图...），比 favicon 图标库更贴合业务。

3. **Emoji 作为功能性图标**：数据健康页的 `📊📈⚠️✅` 使用 emoji，免部署、不 404、跨平台兼容好，符合 AGENTS.md 中的设计原则。

4. **CSS 伪元素图标（小程序）**：用 `::before/::after` 纯 CSS 绘制 home/ball/cup/bars 图标，零额外请求。

#### ⚠️ 存在的问题

**问题1：日期箭头 SVG 在多处重复硬编码**

同一个箭头 SVG path 在 `page-match`、`page-plan`、`page-rank`、`page-quant-rank` 的 date-bar 中各出现 2 次（左+右），即总共重复了 **8 次**，造成 HTML 体积冗余。

**问题2：下拉菜单箭头也在多处重复**

相同的 `<polyline points="6 10 12 16 18 10"/>` 箭头在 filter 页、income 页的多个下拉中重复，合计约 10+ 次。

**问题3：导航 Logo 使用外部 PNG 存在 404 风险**

`/assets/` 映射到 `miniprogram/images/`，该 `logo.png` 是否能正确加载取决于 `miniprogram/images/worldcup/logo.png` 是否存在。存在潜在 404 风险。

**问题4：功守道弹窗图标依赖 `<img>` 外部文件**

CSS 中 `.gs-title-icon` 定义为 `<img>` 的类名样式，渲染时由 JS 动态设置 `src` 属性。如果文件路径不正确，弹窗内图标区域会显示空白或破图。

**问题5：Emoji 与 SVG 混用缺乏统一标准**

- AI 弹窗用 `💡🏆⚽📊`（emoji）
- 方案通知用 `📊`（emoji）
- TabBar 用 inline SVG
- 菜单用 inline SVG
- 日期箭头用 inline SVG 但切换按钮用 `<` `>` 文本字符
- 关闭按钮用 `✕` 文本字符
- 数据健康状态标记用 `✅❌⚠️`（emoji）

### 1.3 图标优化建议

| 优先级 | 建议 | 预期收益 |
|--------|------|---------|
| **P0** | 提取日期箭头 SVG 为 CSS 类（`::before` 或 `background-image`），消除 8 次重复硬编码 | 减少 ~400 字节 HTML |
| **P0** | 提取下拉箭头为 CSS 类（`.filter-dd-arrow` 已有类名，改为 CSS `::after` 绘制） | 减少 ~600 字节 HTML |
| **P1** | 导航 Logo 改为 Inline SVG 或 emoji 替代（`⚽`），消除外部依赖 | 杜绝 404 风险 |
| **P1** | 功守道弹窗图标改为 emoji 内联字符 | 无需部署静态文件 |
| **P2** | 制定图标选用规范文档：Inline SVG（核心 UI） > Emoji（状态标记/功能性） > 外部文件（仅在必须时） | 提升一致性 |
| **P2** | 将日期切换、日历关闭等 `<` `>` `✕` 文本字符也统一为 Inline SVG | 视觉风格统一 |

### 1.4 图标选用规范（建议）

```
优先级：Inline SVG > Emoji 内联字符 > CSS 伪元素 > 外部文件

- 核心 UI 控件（导航、TabBar、菜单）：使用 Inline SVG
- 状态标记、通知提示、功能性装饰：使用 Emoji
- 仅 Logo 等无法替代的品牌资产：使用外部文件
- 简单几何图形（箭头、圆点）：优先 CSS 绘制
```

## 二、提示语/消息使用情况分析

### 2.1 提示语分类汇总

#### A. `alert()` 弹窗（原生浏览器弹窗）

| 文件 | 触发场景 | 文案 | 评价 |
|------|---------|------|------|
| `confirm-scheme.js` | 未选比赛 | `alert('请至少选择一场比赛')` | 基本可用 |
| `confirm-scheme.js` | 单关限制 | `alert('⚽ 胜平负/让球玩法需要该场比赛支持单关投注...')` | 文案过长 |
| `confirm-scheme.js` | 金额超限 | `alert('⚽ 投注金额 ' + amount + ' 元超过单张彩票 20000 元上限...')` | 有⚽ emoji，较好 |
| `confirm-scheme.js` | 奖金超限 | `alert('⚽ 预计奖金 ' + maxWin.toFixed(2) + ' 元超过...')` | 有⚽ emoji，较好 |
| `confirm-scheme.js` | 保存失败 | `alert('保存失败: ' + e.message)` | 无 emoji，信息不足 |
| `confirm-scheme.js` | 无数据 | `alert('暂无方案数据')` | 无 emoji |
| `scheme-design.js` | 玩法限制 | `alert('⚽ ' + PLAY_NAMES[playType] + '玩法最多选择 ' + limit + ' 场比赛...')` | 有⚽ emoji |
| `scheme-design.js` | 未选比赛 | `alert('请至少选择一场比赛')` | 无 emoji |
| `scheme-design.js` | 单关限制 | `alert('⚽ 胜平负/让球玩法需要该场比赛支持单关投注...')` | 有⚽ emoji |
| `scheme-design.js` | 串关冲突 | `alert('串关方案不能包含相同场次（含不同玩法）...')` | 无 emoji |
| `scheme-design.js` | 模块失败 | `alert('投注模块加载失败')` | 无 emoji |
| `main-fusion.js` | AI 加载失败 | `alert('AI深度解析加载失败，请刷新页面后重试')` | 无 emoji |
| `main-fusion.js` | 功守道失败 | `alert('功守道量化数据加载失败，请刷新页面后重试')` | 无 emoji |

**总计**：约 15 处 `alert()` 调用，**emoji 覆盖不完整**（仅 5 处有 ⚽ 前缀）。

#### B. 空值/暂无数据状态（innerHTML 渲染）

| 页面 | 文案 | 样式 |
|------|------|------|
| plans.js 专家方案 | `当日暂无竞彩方案` | 居中灰色文字 |
| plans.js 单关比分 | `📊 今日暂无符合条件的单关比分方案` | 有 emoji 图标 |
| plans.js 我的方案 | `暂无我的方案` (推断) | — |
| filter.js | `暂无符合条件的数据` | loading class 包裹 |
| income.js | `暂无方案收入数据` | hint-box 样式 |
| ranking.js | `暂无排名数据` (推断) | — |
| hit-rate.js | `命中率统计需要时间积累` | loading class 包裹 |
| match-list.js | 空列表 | 无专门空状态，仅列表为空 |

**小程序端**：使用 TDesign 的 `<t-empty>` 组件，如 `"暂无比赛"` `"暂无排名"` `"暂无符合条件的数据"`。

#### C. 加载中状态

| 文案 | 出现频率 | 问题 |
|------|---------|------|
| `加载中...` | 出现 20+ 次 | 太通用，用户不知道在加载什么 |
| `加载方案中...` | 1次（confirm-scheme） | 较好，指明了内容 |
| `加载单关比分方案中...` | 1次 | 较好 |
| `加载量化博冷方案中...` | 推测存在 | - |
| `方案收入加载中...` | 推测存在 | - |

**问题**：绝大多数使用统一模板 `<div class="loading"><div class="loading-spinner"></div>加载中...</div>`，无法区分不同场景。

#### D. 错误/失败状态

| 场景 | 文案 | 表现 |
|------|------|------|
| API 请求失败 | `请求失败，请检查网络` | amber 色文字 |
| 模块加载失败 | `AI深度解析加载失败，请刷新页面后重试` | alert 弹窗 |
| 模块加载失败 | `功守道量化数据加载失败，请刷新页面后重试` | alert 弹窗 |
| 数据查询失败 | `查询失败` | loading class |
| 保存失败 | `保存失败: [具体错误]` | alert 弹窗 |
| 筛选查询失败 | `加载联赛列表失败`（小程序） | Toast |

### 2.2 合理性评估

#### ✅ 做得好的地方

1. **alert 消息有部分 emoji 增强可读性**：如 `⚽` 前缀的投注相关提示。

2. **小程序端统一使用 TDesign 组件**：`<t-loading>` 加载骨架、`<t-empty>` 空状态占位，体验一致。

3. **错误提示有"可操作"引导**：如"请刷新页面后重试"给出了明确的用户操作建议。

4. **加载文案在个别场景有具体化**：如"加载单关比分方案中..."比通用"加载中..."更有信息量。

#### ⚠️ 存在的问题

**问题1：`alert()` 过于粗暴，缺乏统一组件**

原生 `alert()` 弹窗阻塞 UI 线程、样式无法定制、移动端体验差。15 处 `alert()` 散布在 3 个文件中，没有一个项目级的消息提示系统（Toast/Modal）。

**问题2：Emoji 使用不统一**

- `confirm-scheme.js` 中有 4 处带 `⚽` 前缀，3 处不带
- `scheme-design.js` 中有 2 处带 `⚽`，3 处不带
- `main-fusion.js` 中 2 处都不带 emoji
- 加载提示中 `📊` 仅出现 1 次

无法形成"看到 ⚽ 就知道是投注相关提示"的用户心智模型。

**问题3：空值状态设计不一致**

- `plans.js` 的方案空状态用了 `📊 + 文案` 的 notice 样式
- `filter.js` 的空状态用 `.loading` class（不恰当，loading 是加载态）
- `income.js` 用了 `.hint-box`
- 小程序端统一用 `<t-empty>`，但前端预览版没有统一组件

**问题4：加载状态缺乏区分度**

所有页面都用同一个 `<div class="loading">加载中...</div>` 模板，用户无法区分：
- 是网络慢还是服务端慢？
- 正在加载的是比赛数据还是方案数据？
- 加载失败了还是仍在加载？

**问题5：错误提示信息量不足**

```js
alert('功守道量化数据加载失败，请刷新页面后重试');
```

没有告知失败原因（超时？数据不存在？服务端报错？），用户只能盲刷新。

**问题6：缺少操作引导的空状态**

所有空状态文案都是"暂无XX"，缺少引导性操作提示。例如：
- ❌ `当日暂无竞彩方案`
- ✅ `当日暂无竞彩方案，试试切换日期查看其他比赛`

**问题7：前端预览版与小程序端体验割裂**

小程序端使用 TDesign 组件（`t-loading`、`t-empty`、`t-toast`），前端预览版全部是自绘 HTML。两条路径的提示语和交互体验不一致。

### 2.3 提示语优化建议

| 优先级 | 建议 | 说明 |
|--------|------|------|
| **P0** | 建立统一的 Toast 提示函数替代 `alert()` | 创建 `showToast(msg, type)` 函数，支持 success/error/warning/info 类型，顶部弹出自动消失，不阻塞 UI |
| **P0** | 统一 Emoji 前缀规范 | 投注相关 → `⚽`，数据相关 → `📊`，错误 → `⚠️`，成功 → `✅`，信息 → `💡` |
| **P1** | 创建 `<EmptyState>` 渲染函数 | 统一空状态组件：`renderEmpty(icon, title, desc, actionText, actionFn)` |
| **P1** | 加载文案具体化 | `加载中...` → `正在加载比赛数据...` / `正在生成方案列表...` |
| **P1** | 错误提示增加原因和解决方案 | `功守道数据加载失败` → `⚠️ 功守道数据加载失败（网络超时），点击重试` |
| **P2** | 空状态增加操作引导 | `暂无方案` → `📋 暂无方案数据，去方案设计页创建新方案 →`（带跳转按钮） |
| **P2** | 建立提示语文案表 | 将所有提示语集中管理在一个配置文件中，方便统一维护和多语言扩展 |
| **P3** | 考虑 Skeleton Screen | 替代通用 loading spinner，用骨架屏减少用户感知等待时间 |

### 2.4 Emoji 使用规范（建议）

```
⚽  投注相关操作提示（下注、选场、金额、奖金）
📊  数据/方案/统计相关提示
⚠️  警告/错误提示
✅  成功/完成确认
💡  信息性提示/建议
📋  空状态/暂无数据
🔄  加载/处理中
🔔  通知提醒
```

### 2.5 建议实现示例

#### 统一 Toast 函数

```javascript
// preview/js/toast.js
function showToast(msg, type) {
  type = type || 'info';
  var emojiMap = { success: '✅', error: '⚠️', warning: '⚡', info: '💡' };
  var toast = document.createElement('div');
  toast.className = 'toast toast-' + type;
  toast.innerHTML = '<span class="toast-icon">' + (emojiMap[type] || '') + '</span>' + msg;
  document.body.appendChild(toast);
  setTimeout(function() { toast.classList.add('toast-out'); }, 2500);
  setTimeout(function() { toast.remove(); }, 3000);
}
```

#### 统一空状态组件

```javascript
function renderEmpty(container, icon, title, desc, action) {
  var html = '<div class="empty-state">';
  html += '<div class="empty-icon">' + (icon || '📋') + '</div>';
  html += '<div class="empty-title">' + title + '</div>';
  if (desc) html += '<div class="empty-desc">' + desc + '</div>';
  if (action) html += '<button class="empty-action" onclick="' + action.onClick + '">' + action.text + '</button>';
  html += '</div>';
  container.innerHTML = html;
}
```

## 总结

| 维度 | 当前状态 | 核心问题 | 优化方向 |
|------|---------|---------|---------|
| **图标复用** | SVG 重复硬编码 8+ 次 | HTML 体积冗余 | CSS 类抽取 |
| **图标一致性** | Inline SVG / Emoji / 文本字符 / 外部文件混用 | 风格不统一 | 制定选用规范 |
| **图标稳定性** | Logo 和功守道图标依赖外部文件 | 潜在 404 风险 | 迁移为 Inline SVG / Emoji |
| **提示语系统** | `alert()` 15 处散布 3 文件 | 阻塞 UI，不可定制 | 统一 Toast 组件 |
| **Emoji 规范** | 仅 5/15 处 alert 有 emoji | 无心智锚点 | 建立前缀规范 |
| **空状态** | 4 种不同样式混用 | 体验割裂 | 统一 EmptyState 函数 |
| **加载提示** | 20+ 处通用 `加载中...` | 信息量不足 | 场景化文案 |
| **双端一致** | 小程序 TDesign vs 前端自绘 | 两条路径分化 | 尽量靠近 |
