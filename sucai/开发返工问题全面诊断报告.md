## 概述

经对全仓库 754 个 commit 的系统性盘查，共识别出 **22 个高频返工问题**，分为两大类：

| 类别 | 数量 | 来源 |
|------|------|------|
| 用户已感知 | 11 个 | 开发者日常体验 |
| 深度盘查发现 | 11 个 | git log + 文件变更模式分析 |

所有问题可归纳为 **3 个根因**：

1. **缺乏自动化门禁** —— 缓存、部署、测试、性能监控全靠人肉
2. **缺乏设计先于编码** —— UI 无验收标准、参数无量化验证、技术选型无本地完整测试
3. **已有工具/Skill 未被真正使用** —— experiment-tracking、backtesting-frameworks 形同虚设

## 第一类：用户已感知的问题（11 个）

### 1. 加功能后系统打开很慢

| 维度 | 详情 |
|------|------|
| **现象** | 每次大功能上线后首页加载变慢，最近一次优化前达 16~25s |
| **根因** | 性能优化是一次性的，缺乏持续的性能回归门禁 |
| **返工证据** | commit `09d4bb09` 标题为"P0+P1 系统性性能优化"，说明之前已经退化到不可接受 |
| **解决方案** | ① 建立性能基准测试（首页 < 2s、功守道 < 3s、方案页 < 3s） ② preflight 强制加入性能基准对比 ③ 自动化探针每日监控（已有 `scheme_slow_probe_*.cjs` 未固化） |

### 2. 数据反反复复的修

| 维度 | 详情 |
|------|------|
| **现象** | 数据相关问题反复出现：跨日比分、赔率修复、方案收入修正、数据漂移 |
| **根因** | 数据层缺乏统一的质量门禁和自动化校验，多源数据格式不一致 |
| **返工证据** | `data_sync.js` 25+ 个 commit，多数为数据修复；`prediction_log.js` 绕过 adapter 写 raw 导致数据丢失 |
| **解决方案** | ① 建立数据质量门禁（extract ≥ 90%, load ≥ 90%，不通过阻断） ② 统一数据入口 `match-data-pack` ③ 自动化数据对账脚本 |

### 3. 颜色改动一直做不出来

| 维度 | 详情 |
|------|------|
| **现象** | 颜色改动涉及多次反复：橙色 #FF8C00、紫色 #A78BFA、蓝色 #00E5FF、绿色按钮、红/绿箭头 |
| **根因** | 颜色硬编码分散在多个文件中，缺乏 CSS 变量体系 |
| **返工证据** | `app.css` 80+ 个 commit，其中大量是颜色微调和覆盖修正 |
| **解决方案** | ① 建立 CSS 设计 Token（`:root` 中统一定义 `--color-*`） ② 全局替换硬编码颜色 ③ 每次改色按 Checklist 逐页确认 |

### 4. 同样的错误反复出现

| 维度 | 详情 |
|------|------|
| **现象** | 绕过 database.js 写 raw、依赖遗漏导致 500、新页面路由缺失、时区 UTC 问题 |
| **根因** | 经验教训只记录在 Skill 文件/AGENTS.md 中，无自动化检查阻挡 |
| **返工证据** | AGENTS.md 累积 25+ 条教训，deploy-ops Skill 10+ 条，但同类错误仍在发生 |
| **解决方案** | ① 建立 pre-commit 自动检查脚本（依赖追踪、raw 绕过检测、时区函数检测） ② 将 5 大犯错模式固化为自动化检查 |

### 5. 比赛开赛时间跨日期问题

| 维度 | 详情 |
|------|------|
| **现象** | 北京时间 00:00~07:59 被 UTC 时区算成前一天；竞彩编号跨周重复导致数据混乱 |
| **根因** | 时区处理不是全局统一的，各处散落不同日期处理方式 |
| **返工证据** | AGENTS.md §9.7 专项记录；commit `3afebfb0` 引入 `fmtLocal()` 修复；`sync_live_500.js` 整点崩溃 |

## 第二类：深度盘查发现的隐藏问题（11 个）

### 12. 手动版本戳地狱

| 维度 | 详情 |
|------|------|
| **现象** | 修改前端代码后必须手工改版本戳来强制浏览器刷新缓存 |
| **返工证据** | 至少 10+ 个 commit 仅为了 bump 版本号 |
| **典型 commit** | `f98bf8f9` 版本戳刷 plan_icon 缓存；`c250d71a` 刷新足球 icon 缓存；`74b6722d` 强制前端 rebuild；`c4a0e9d7` 版本戳 202606101600→202606120300 |
| **根因** | 5 层缓存（内核页 → Nginx → SW → 浏览器 → 模块）没有统一的自动失效机制 |
| **解决方案** | 部署脚本自动注入 `?v=COMMIT_HASH` 查询参数到 HTML 中的 JS/CSS 引用，无需手工改源文件 |

### 13. 缓存多层击穿循环

| 维度 | 详情 |
|------|------|
| **现象** | 部署后改动不生效 → 逐层排查缓存 → 暴力清除 → 下次又来 |
| **返工证据** | ~30 个 commit 涉及缓存修复 |
| **典型 commit** | `cd94e76d` 完全重启 Nginx 清除 open_file_cache；`ceb55960` `drop_caches` 刷新内核页缓存；`594b7dfe` cp 后 sync 强制刷盘；`91d9c6ef` 添加二次验证+强制重写 index.html |
| **涉及的缓存层** | 内核页缓存 → Nginx open_file_cache → Nginx expires → SW Cache → 浏览器 HTTP 缓存 → 模块懒加载缓存 |
| **解决方案** | ① 绘制缓存失效层级图 ② 部署脚本按层级自动逐层失效 ③ 禁止手工 drop_caches 和 chattr 操作 |

### 14. 部署工具 deploy.py 自身不稳定

| 维度 | 详情 |
|------|------|
| **现象** | `deploy.py` 自身需要频繁修复，commit 数远超任何业务文件 |
| **返工证据** | ~70 个 commit 修改 `deploy.py` |
| **典型问题** | SFTP 权限失败 → 改用 base64+SSH 管道 → 再恢复 SFTP；MD5 比对控制字符问题；临时文件命名 hash 冲突；grep 计数假阴性；目标路径错误；chattr 不可变文件 |
| **根因** | Shell 命令拼接 + SFTP + SSH 组装的胶水脚本，边界 case 极多 |
| **解决方案** | ① 考虑用 `rsync` 替代手工 SFTP ② 或将部署逻辑改写为 Node.js 脚本（减少技术栈碎片） ③ 建立 deploy.py 的 dry-run 集成测试 |

### 15. 管理后台 UI 反复推倒重来

| 维度 | 详情 |
|------|------|
| **现象** | 管理后台 UI 框架和 CSS 多次推翻重建 |
| **返工证据** | 9+ 个 commit 仅关于管理后台 UI |
| **演变路径** | `admin.css v2 → v3 → v4 → Shoelace Web Components → 暗色主题局部注入 → revert 撤回 Shoelace → 回 admin.css v3` |
| **根因** | 新框架/新技术上线前未在本地完整验证，遇到兼容性问题再回退 |
| **解决方案** | ① 禁止在生产分支上直接试验新技术栈 ② 新框架必须在本地完整验证（所有功能+浏览器+屏幕尺寸） ③ 管理后台优先级低，功能可用即可，不过度工程化 |

### 16. 方案参数"魔法数字"反复调参

| 维度 | 详情 |
|------|------|
| **现象** | 方案生成器的参数频繁微调，没有量化依据 |
| **返工证据** | 8+ 个 commit 涉及方案参数调整 |
| **典型 commit** | `minExpertA 2→3→2` 反复横跳；`minOdds=1.0`；`minProduct=1.5` 来回调整 |
| **根因** | 方案质量依赖"感觉"而非回测数据；已有的 `backtesting-frameworks` Skill 从未被使用 |
| **解决方案** | ① 每次调参先在回测框架中跑历史数据验证 ② 参数写入配置文件（`plan-config.json`）而非硬编码 ③ 每次调参用 `experiment-tracking` Skill 记录对比数据 |

### 17. 数据回填脚本散落各处

| 维度 | 详情 |
|------|------|
| **现象** | 数据缺失时临时写一个回填脚本，用完就丢，下次又重新写 |
| **返工证据** | 至少 5 个独立回填入口分散在不同位置 |
| **文件清单** | `server/backfill_full_models.js`（模型回填）；`server/bulk_outcome.js`（赛果回填）；`scripts/backfill_consensus.js`（共识回填）；`server/data_sync.js` 内 finalCheck（增量同步）；`prediction_log.js` 绕过 adapter 导致数据丢失后再回填 |
| **根因** | 无统一的数据修复入口，每次场景临时写脚本 |
| **解决方案** | ① 合并到 `server/backfill/` 统一目录 ② 每个回填操作必须幂等 ③ 统一入口 `backfill/index.js` 暴露 `backfill.all()` 方法 |

### 18. Commit 质量严重不一致

| 维度 | 详情 |

| **解决方案** | ① 禁止堆砌式提交 ② Git hooks 强制 commit message 格式检查 ③ `npm run preflight` 通过后才能 commit |

### 19. 静态资源路径反复折腾（图标 404 循环）

## 根因收敛：3 大类

### 根因一：缺乏自动化门禁

涉及问题：#1 #2 #4 #5 #7 #8 #12 #13 #14 #18 #20 #22

### 根因二：缺乏设计先于编码

涉及问题：#3 #15 #16 #19 #21 #22

**表现**：UI 无验收标准、参数无量化验证、技术选型未本地完整测试、AI 切换无对比数据。

**核心举措**：

```
功能开发前置条件
 ├── UI 功能：出验收 Checklist（布局/颜色/交互/边界）→ 自测通过 → commit
 ├── 算法调参：先在回测框架跑历史数据 → 命中率/ROI 说话 → 记录 experiment-tracking
 ├── 技术选型：本地完整验证（全部功能+全部浏览器+全部屏幕）→ 通过 → 上线
 └── AI 变更：记录命中率对比 + 成本对比 → 数据驱动决策

CSS 变量体系
 ├── :root 统一定义 --color-*, --font-*, --radius-*, --spacing-*
 ├── 全局替换硬编码值
 └── 变色 = 改一处，全站生效
```
