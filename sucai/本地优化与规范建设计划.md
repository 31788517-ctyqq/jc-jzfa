### N1. 根目录临时 Python 脚本泛滥

```
根目录 53 个 .py 脚本（排除 deploy.py / backup_db.py）:
  _rebuild_db.py   _rebuild2.py   _rebuild3.py   _recover_and_import.py
  _fix_sync.py     _fix_gaps.py   _fix_allplays.py  _diag8.py  _diag9.py
  _diagnose_db.py  _check_tables.py  _check_integrity.py  _unlock_db.py
  _verify_final.py  _verify_final2.py … _verify_final5.py
  run_outcome_backfill.py  check_phase3_scope.py  debug_live.py
  … 还有 ~30 个
```

**根因**：每次服务器问题或数据修复，本地写一个 Python 脚本直连服务器操作。用完不删。

**优化措施**：
- 归档到 `scripts/archive/` 或直接删除
- 常用的固化为 `scripts/db_tools.py` 统一入口
- 在 `.gitignore` 中忽略 `_*.py` 模式

### N2. `!important` 严重滥用

```
app.css:   282 处 !important
modals.css: 51 处 !important
```

**根因**：CSS 优先级管理失控，用 `!important` 暴力覆盖。

**优化措施**：
- CSS 变量化后会自然减少（一个变量改全站）
- 制定规则：新 CSS 禁止 `!important`，除非覆盖第三方库
- 逐步排查并移除不必要的 `!important`

### N3. `innerHTML` 直接赋值蔓延

```
30 个前端文件中存在直接 innerHTML 赋值:
  plans.js: 27 处, admin.js: 24 处, main-fusion.js: 30 处
  backtest.js: 16 处, home.js: 12 处, scheme-design.js: 11 处
  bet component: 13 处 (ec-canvas/echarts.js)
```

**风险**：XSS 注入漏洞 + DOM 全量重绘导致性能问题。

**优化措施**（低优先级，不急于改）：
- 新代码用 `textContent` 替代纯文本 innerHTML
- 需要 HTML 的场景使用 `createElement` + `appendChild`
- 为动态内容添加 HTML 转义函数

### N4. app.css 臃肿

```
app.css: 301.7 KB / 14,870 行
  → 单文件比大多数完整前端框架还大
```

**根因**：所有页面样式全堆在一个文件 + 多次 UI 调整叠加旧样式未删除。

**优化措施**：
- CSS 变量化时会自然清理不必要重复的色值定义
- 排查并删除从未使用的 CSS 规则
- 长期考虑按页面拆分为 CSS 模块（`home.css`, `plans.css` 等）

### N5. server/ 下独立 JS 直接操作 DB

```
server/catch_up.js        — 追赶历史数据
server/catch_up_standalone.js  — 独立运行版
server/crawl_all.js       — 全量爬取
server/batch_fetch_500all.js / batch_fetch_500_all.js  — 重复功能
server/batch_fetch_odds.js
server/oneshot_sync.js    — 一次性同步
```

**风险**：绕过 `data_sync.js` 的调度/质量门禁/错误处理，直接操作数据库。

**优化措施**：
- 这些脚本的逻辑应收敛到 `data_sync.js` 或 `scripts/` 中
- 禁止在 `server/` 下新增独立运行脚本
- 清理明显重复的（`batch_fetch_500all.js` vs `batch_fetch_500_all.js`）

### 3.1 创建 `server/core/datetime.js` ⬜

消灭时区问题。创建后需在 `deploy.py` 的 DEPLOY_MAP 中追加。

```javascript
// server/core/datetime.js
const CN_OFFSET = 8 * 60 * 60 * 1000;
function cnNow() {
  const now = new Date();
  return new Date(now.getTime() + CN_OFFSET - now.getTimezoneOffset() * 60000);
}
module.exports = {
  todayCN() { return cnNow().toISOString().slice(0, 10); },
  nowISO()  { return cnNow().toISOString(); },
  fmtCN(d)  { return new Date(new Date(d).getTime()+CN_OFFSET).toISOString().slice(0,10); },
  matchKey(date, num) { return `${date}|${num}`; },
};
```
